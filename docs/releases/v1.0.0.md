## Database, Auth, and recovery

The reviewed production migrations enforce matching thread/message ownership,
restrict external execution of the privileged event-trigger function, preserve
its `postgres` ownership and enabled trigger, and add the covering ownership
index. Auth and cross-user RLS tests used disposable fictional identities.

The encrypted Supabase archive, DPAPI-protected recovery key, and protected
final database credential remain outside OneDrive. The newest archive's
recorded SHA-256 was reverified on 2026-08-31 without decrypting it or displaying
records. Database recovery is separate from code or deployment rollback.

## Online AI and deterministic fallback

- Provider: Cloudflare Workers AI.
- Model: `@cf/meta/llama-3.1-8b-instruct-fp8`.
- Prompt: the existing Hibalag system prompt and schedule-grounding rules,
  unchanged.
- Shared bindings: Workers AI plus one SQLite Durable Object quota namespace.
- Server-only secret: the same undisclosed `AI_RATE_LIMIT_PEPPER` value on both
  deployments.
- Emergency switch: `AI_ENABLED=false` disables inference and fails closed.

Signed-in Supabase bearer tokens are validated before account quotas are used.
Guest/IP and user identifiers are HMAC-pseudonymized before the shared quota
object receives them. The application does not intentionally log raw
identities, IP addresses, tokens, prompts, conversations, responses, schedule
text, or secrets.

Limits are 5 requests per minute and 20 per UTC day for each signed-in user, 3
per minute and 10 per UTC day for each guest/IP identity, and 20 accepted
requests per UTC day globally across Pages and Worker. The account-wide 10,000
Neuron daily free allocation remains the final fail-closed limit. No paid
fallback, overage, trial, or billing activation is permitted.

The 15-second application timeout bounds how long Hibalag waits before offering
the deterministic fallback. Cloudflare does not currently document an
application-controlled cancellation signal for `env.AI.run()`, so an accepted
inference may continue using free Neurons after Hibalag times out. Timed-out
requests remain quota-counted and are not automatically retried.

When AI is disabled, exhausted, unavailable, malformed, or timed out while the
browser is online, the application identifies live AI as unavailable and offers
the deterministic assistant. A genuinely offline browser uses cached schedules
and deterministic offline responses.

## Provider data use and model terms

Cloudflare receives the bounded system prompt, public schedule context, and
conversation text required for inference. Hibalag does not intentionally send
email addresses, raw Supabase user IDs, raw IP addresses, bearer tokens,
credentials, quota identities, or private database records to the model.

Cloudflare documents prompts and outputs as customer content. It states that it
does not make that content available to other Cloudflare customers and does not
use it to train AI models or improve Cloudflare or third-party services without
explicit consent. Hibalag does not configure AI prompt or response storage; its
Durable Object stores only pseudonymous counters. See the current
[Workers AI data-usage policy](https://developers.cloudflare.com/workers-ai/platform/data-usage/).

The model is Cloudflare-hosted and supplied by Meta as a third-party service.
Use remains subject to Cloudflare's applicable terms and the model's linked
license and acceptable-use terms. Recheck the
[model page](https://developers.cloudflare.com/workers-ai/models/llama-3.1-8b-instruct-fp8/)
before a future model or commercial-use decision.

Built with Llama.

## Production verification

Exact `main` commit `fe31fe826336f9d5e2bade37cb323a5d08194e45`
passed TypeScript, focused lint and formatting, 28 focused tests, the independent
Nitro build, and Pages and Worker packaging checks with `LOVABLE_API_KEY` absent.

Both production deployments were first verified with AI disabled. Each then
received exactly one short fictional request. Both returned HTTP 200 with a
non-empty, schedule-grounded answer from the reviewed model. Response content
was not printed or retained. The home page, manifest, service worker, and
Workbox runtime returned successfully. No production records were used.

Cloudflare remained on the Free plan. Workers AI Free includes 10,000 Neurons
per day, and SQLite Durable Objects on Workers Free include their own hard free
limits. Additional operations fail when free allowances are exhausted; paid
usage was not enabled. Pages Functions and the Worker share the account's free
allowances.

## Known limitations

- Production Pages hard-offline behavior relies on identical-package local and
  Worker evidence because blocking system networking would be disruptive.
- Cloudflare did not expose a reliable per-request Neuron figure during the
  verification window; the two approved requests consumed part of the shared
  daily free allocation.
- Full production email delivery, recovery, and expiry journeys remain manual.
- Supabase leaked-password protection remains disabled.
- A database archive does not include every managed dashboard setting, secret,
  log, or external service configuration.
- Both deployments share one Cloudflare account and are not independent of an
  account-wide Cloudflare outage or exhausted shared quota.

## Rollback

AI emergency rollback: set `AI_ENABLED=false` on the affected deployment and
verify deterministic fallback. Do not remove bindings or secrets during an
incident.

Worker deployment rollback: restore version
`643389ce-7798-4332-b5ca-bbe655ccf903` to 100% traffic, then verify the public
Worker URL. The newer disabled version
`5cda8539-f57b-4b07-90e9-06f4f2b594bc` is also available for an AI-off rollback.

Pages deployment rollback: restore deployment
`e3375360-7bb8-4f4d-85df-2ea288509d31`, then verify the primary URL. Keep the
Worker available while Pages is repaired.

Code rollback: revert the faulty shared commit through a reviewed pull request;
never rewrite published history. Deployment of a revert requires separate
approval.

Database structure: use the migration-specific rollback under
`docs/preservation`, then repeat Auth, RLS, constraint, trigger, and advisor
checks. Data recovery: verify the encrypted archive and restore into an isolated
compatible environment before any separately approved production recovery.

A Git or Cloudflare rollback does not reverse a database migration or restore
changed or deleted records.
